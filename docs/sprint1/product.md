# Характеристика продукту й контексту «ШопЛайн»

## 1. Профіль компанії і продукту
**ТОВ «ШопЛайн»** — житомирська e-commerce компанія (заснована у 2019 році), що спеціалізується на продажі ручного та електроінструменту, садового обладнання й витратних матеріалів. Компанія має один склад, пропонує близько 600 товарних позицій та доставляє замовлення по всій Україні через поштових операторів.

**Контекст розробки та технічний стек:**
*   **Архітектура:** Вебзастосунок з односторінковим інтерфейсом (SPA).
*   **Фронтенд:** Angular.
*   **Бекенд:** REST API на PHP (фреймворк Laravel).
*   **База даних:** MySQL.
*   **Інтеграції:** Зовнішній платіжний шлюз для онлайн-оплат.

Штат компанії налічує 28 працівників. Релізи продукту відбуваються кожні два тижні. Відділ забезпечення якості (QA) було створено нещодавно, оскільки раніше тестуванням займалися самі розробники, і наразі найбільша кількість скарг від користувачів стосується роботи кошика та процесу оформлення замовлення. Стратегічна мета керівництва — підвищити відсоток клієнтів, які повертаються за новими покупками.

## 2. Користувачі та ролі
У системі діють такі ключові ролі:
*   **Покупець (гість або авторизований):** Основний користувач продукту. Шукає товари, використовує фільтри, керує кошиком та списком обраного, оформлює покупки. У кабінеті може переглядати історію замовлень (інвойси), читати повідомлення та писати у підтримку через контактну форму.
*   **Менеджер магазину:** Відповідає за операційну діяльність. Обробляє нові замовлення, відповідає на звернення покупців, проводить процедури повернення товару, відстежує складські залишки та формує замовлення для постачальників.
*   **Адміністратор:** Має повний доступ до бекофісу. Керує наповненням каталогу (додає/редагує товари, категорії, бренди), змінює глобальні налаштування системи та управляє обліковими записами.
*   **Зовнішні учасники (пули):** Платіжний шлюз, поштова служба доставки та постачальники. Вони не є прямими користувачами інтерфейсу, але обмінюються системними повідомленнями з «ШопЛайн».

## 3. Бізнес-процеси
З чотирьох ключових процесів компанії, наведених у каталозі, наша команда обрала для детального моделювання в нотації BPMN 2.0 наступні три:
1.  **Оформлення замовлення** (Залучені учасники: Покупець, Магазин).
2.  **Повернення товару** (Залучені учасники: Покупець, Магазин, Служба доставки).
3.  **Обробка звернення з контактної форми** (Залучені учасники: Покупець, Магазин).

*Четвертий процес («Поповнення складу») залишено поза обсягом моделювання для поточного спринта.*

## 4. Замовлення й очікування
**Контекст замовлення:** Керівництво стурбоване тим, що 50% клієнтів здійснюють лише одну покупку. Для розв'язання цієї проблеми ініційовано розробку «Програми лояльності» з підтримкою промокодів. Головна вимога: впровадження нових фіч не повинно ускладнити існуючий флоу оформлення замовлення.

**Конкретні очікування до нової функції:**
1.  **Бонусна система:** За кожне успішно оплачене замовлення покупцю нараховуються бали. Їх баланс відображається в особистому кабінеті, і клієнт може використовувати їх для часткової оплати майбутніх покупок.
2.  **Застосування промокодів:** У кошику з'являється поле для промокоду. Система повинна автоматично перевіряти його валідність (формат, чи не минув термін дії, чи не був він уже використаний, якщо він одноразовий) і одразу перераховувати суму до оплати.
3.  **Знижка від суми (Volume Discount):** Система має автоматично надавати знижку залежно від загальної вартості кошика. Передбачено три рівні порогів, і застосовуватись має лише той, що дає найбільшу вигоду клієнту.
4.  **Безкоштовна доставка:** Якщо після застосування всіх промокодів та знижок сума замовлення все ще перевищує встановлений поріг, доставка стає безкоштовною. Інформація про цей поріг має бути помітною в кошику.
5.  **Інструменти менеджера:** Менеджер отримує функціонал для генерації нових промокодів (може задавати знижку у відсотках або фіксованій сумі, встановлювати дедлайн дії та робити код одноразовим). Також він має доступ до статистики їх використання.
6.  **Налаштування адміністратора:** Адміністратор системи отримує можливість самостійно змінювати курс конвертації бонусних балів та суму порогу для безкоштовної доставки через адмін-панель (без потреби правити код бази даних).
