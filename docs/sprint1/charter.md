### 1.4. Методологія роботи команди

| Рівень | Що застосовує ваша команда | Приклад формулювання |
|---|---|---|
| **Методологія** | **Agile / Полегшений Scrum** | Полегшений Scrum: 5 двотижневих спринтів, Sprint Planning, Sprint Review (Demo), Retrospective, ротація ролей (Скрам-майстер, Рецензент, QA/BA аналітики) між спринтами. |
| **Методи** | **User Stories, BPMN-моделювання, Peer Review за чек-листами, Matched Traceability** | Опис функціональних вимог через User Stories (INVEST); візуалізація бізнес-процесів у нотації BPMN 2.0; перевірка артефактів за чек-листами якісності; трасування «Очікування замовника → US → BPMN → Тест-кейс». |
| **Прийоми** | **Standup у Discord/Telegram, Start/Stop/Continue, схема «1 виконавець — 1 рецензент», Feature Branch Workflow** | Асинхронні щоденні стендапи в командному чаті; ретроспектива у форматі Start / Stop / Continue; закріплення за кожною задачею одного виконавця та одного рецензента перед коммітом у `main`; створення окремих гілок під артефакти та використання Pull Request / Direct Commit з обов'язковим рев'ю. |
