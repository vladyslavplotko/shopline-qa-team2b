## Частина 2. Чек-лист перевірки якості User Stories (US-01 ... US-12)

| № | Критерій якості | Статус | Зауваження |
|---|---|:---:|---|
| **1** | **Формат "Як [роль] я хочу [дія] щоб [мета]"** | **Так** | Усі 12 сторіс чітко дотримуються канонічної структури (Роль, Бажання, Мета). |
| **2** | **Атомарність та незалежність (Independent)** | **Так** | Кожна сторіс описує окрему функцію (наприклад, US-03 — введення, US-10 — видалення промокоду). |
| **3** | **Адаптивність / можливість обговорення (Negotiable)** | **Так** | Описано сутність бажаного результату без жорсткої прив'язки до деталей реалізації коду. |
| **4** | **Цінність для користувача/бізнесу (Valuable)** | **Так** | Кожна сторіс містить чітко сформульовану бізнес-мету в колонці «Мета». |
| **5** | **Можливість оцінки (Estimable)** | **Так** | Обсяг робіт зрозумілий, вимоги не містять двозначностей для розробників. |
| **6** | **Компактність / розмір (Small)** | **Так** | Функціонал розбито на невеликі ітеративні кроки (наприклад, налаштування та перегляд логів розділені). |
| **7** | **Тестованість (Testable)** | **Так** | Примітки містять чіткі граничні умови та тестові сценарії (формат, межі 1..50%, логічні перевірки). |
| **8** | **Повнота покриття вимог замовника** | **Так** | Усі 6 очікувань замовника з матриці відстежуваності повністю перекриваються сторісами US-01...US-12. |
| **9** | **Пріоритеризація** | **Так** | Для кожної сторіс проставлено бізнес-пріоритет (High / Med / Low) за методологією MoSCoW. |
| **10** | **Наявність негативних та крайніх сценаріїв** | **Так** | Вказано перевірки для від'ємних балансів, прострочених кодів, порожніх списків та некоректних вводів. |
