## 1. Призначення та обсяг тестування

### 1.1 Мета

Мета плану — визначити рівні й типи тестування, конкретні сценарії, критерії успіху, пріоритети, інструменти та обмеження для перевірки каталогу, кошика, оформлення замовлення, особистого кабінету й Java-модуля бізнес-логіки.

### 1.2 Об’єкти та межі

Тестування поділено на два об’єкти, які не слід ототожнювати:

1. **Публічний demo-вебзастосунок:** `https://practicesoftwaretesting.com`. На ньому перевіряються доступні через GUI сценарії каталогу, кошика, входу, особистого кабінету, контактної форми та оформлення замовлення. Це сторонній демонстраційний продукт, тому результати характеризують доступну demo-версію, а не підтверджують автоматично якість окремого продукту «ШопЛайн».
2. **Java-бібліотека бізнес-логіки:** класи `Cart`, `DiscountCalculator`, `PromoCodeValidator`. Її модульні й інтеграційні тести виконуються окремо від вебзастосунку.

Адміністративна панель, керування товарами/користувачами та нарахування бонусних балів виключені з перевірок GUI версії 1.0. Функціональність, якої немає в публічному demo, не позначається як успішно перевірена: фіксується обмеження середовища або невідповідність між SRS та demo.

## 3. Інструменти, середовище та тестові дані

### 3.1 Середовище

- **Demo URL:** `https://practicesoftwaretesting.com`.
- **Браузери:** Chrome 120+ і Firefox 115+ на настільній ОС.
- **Мобільний viewport:** 375 px у Chrome DevTools.
- **Java-модуль:** JDK 17, Maven, JUnit 5; тести виконуються локально в ізольованому середовищі.
- **Обмеження:** команда не має доступу до коду, серверної конфігурації, БД та резервних копій стороннього demo. Навантажувальні/стресові тести проти публічного сервісу не запускаються без дозволу власника.

### 3.2 Тестові облікові записи та дані

- **Покупець demo:** `customer@practicesoftwaretesting.com`; пароль використовується з актуальної командної копії SRS/узгодженого сховища тестових даних і не дублюється в цьому плані.
- **Гість:** приватне вікно браузера без авторизації.
- **Адміністратор:** не використовується для тестування адмінпанелі, оскільки вона поза обсягом GUI версії 1.0.
- **Каталог:** один доступний товар із відображеною ціною; перед кожним прогоном перевірити доступність товару.
- **Java-бібліотека:** контрольні SKU з непорожніми `sku` і `name`, набори цін, граничні кількості, коректні/некоректні промокоди.
- **Учасники usability/beta:** п’ять учасників; не використовувати реальні платіжні дані та не завершувати реальну оплату.

## 4. Критерії початку та завершення

### 4.1 Критерії початку

- demo відкривається й проходить smoke-перевірку;
- тестові облікові дані доступні через узгоджене командне сховище;
- для Java-бібліотеки доступні вихідний код і тестове середовище;
- тест-кейси та контрольні дані підготовлені;
- власник середовища погодив будь-яке навантажувальне тестування, якщо воно заплановане.

### 4.2 Критерії завершення

- усі сценарії мають статус: пройдено, не пройдено, заблоковано або незастосовно;
- усі дефекти мають кроки відтворення й докази;
- критичні сценарії каталогу, кошика та доступу до кабінету виконані або їх блокування документовано;
- JUnit-тести завершені, результати збережені;
- невідповідності між SRS 1.1 і стороннім demo відокремлені від дефектів продукту.

## 5. Ризики та припущення

- **Скидання даних:** публічне demo може скидати дані або змінювати доступність товарів. Перед кожним прогоном перевіряти передумови й повторно створювати потрібний стан.
- **Стороннє середовище:** команда не контролює сервер, код і БД demo. Результати вимірювань продуктивності не є остаточним підтвердженням характеристик продукту «ШопЛайн».
- **Відмінність вимог від demo:** GUI-10 описує перемикач мови, але demo може не надавати цієї функції. У такому разі записується обмеження/розбіжність, а не успішний результат.
- **Навантаження:** P-20 потребує 100 одночасних покупців протягом 10 хв; виконання можливе лише на погодженому стенді/API. Публічне demo не навантажувати без дозволу.
- **Неповна перевірка безпеки:** через відсутність доступу до серверної конфігурації неможливо підтвердити bcrypt, TLS і повний результат OWASP-сканування лише ручними GUI-тестами.
- **Бета-вибірка:** 5 учасників — реалістичний навчальний обсяг для доступного demo, але не еквівалент повномасштабного бета-тестування 50 користувачами.
- **Java-бібліотека й demo — різні об’єкти:** результати тестів `Cart`, `DiscountCalculator` і `PromoCodeValidator` не доводять, що ці класи інтегровані у сторонній вебзастосунок.

## 6. Результати та звітність

Для кожного сценарію зберігаються: ID тест-кейсу, дата/час, середовище, передумови, тестові дані без паролів, кроки, очікуваний і фактичний результати, статус, скриншот або лог та ID пов’язаного дефекту.

Статуси:
- **Пройдено** — фактичний результат відповідає критерію.
- **Не пройдено** — результат не відповідає критерію.
- **Заблоковано** — виконання неможливе через відсутність доступу, функції, дозволу чи передумов.
- **Незастосовно** — тип тестування не відповідає природі продукту або об’єкту, із зазначеним обґрунтуванням.

Підсумковий звіт має окремо показувати результати для demo-вебзастосунку та Java-бібліотеки, кількість пройдених/непройдених/заблокованих сценаріїв, відкриті дефекти й обмеження середовища.
